# 리마인더

매니저가 등록한 스케줄을 스트리머가 확인하고 완료 처리하는 내부용 리마인더 웹앱입니다.
각 스트리머는 자신에게 매칭된 매니저와만 리마인더를 주고받으며, 다른 매니저·스트리머의
일정은 서로 볼 수 없습니다.

배포: https://reminder-beta-pearl.vercel.app (Vercel, `master` push 시 자동 재배포)

## 스택

- Next.js 16 (App Router) + TypeScript + Tailwind CSS
- Prisma + PostgreSQL (Neon)
- Auth.js (NextAuth v5) — 아이디/비밀번호 로그인, 자체 회원가입 없음

## 시작하기

```bash
npm install
npm run dev
```

`http://localhost:3000` 에서 확인할 수 있습니다. `.env`의 `DATABASE_URL`이 배포와
동일한 Neon DB를 가리키고 있으니, 로컬에서 실행해도 실제 프로덕션 데이터를 다룹니다.

## 계정

셀프 회원가입은 없습니다. 최초 관리자 계정 하나만 시드 스크립트로 만들고, 이후
매니저/스트리머 계정은 관리자가 로그인해서 **계정 관리(`/admin`)** 화면에서 직접
만들고 관리합니다.

```bash
npm run db:seed
```

처음 실행하면 관리자 1개, 매니저 2개, 스트리머 3개 계정이 매니저-스트리머 매칭과
함께 생성되고, 아이디/비밀번호가 `CREDENTIALS.local.md` 파일(git에는 커밋되지
않음)에 저장됩니다. 로그인 후 우측 상단 **설정** 메뉴에서 비밀번호를 변경할 수
있습니다. 이미 존재하는 아이디는 건너뜁니다.

## 권한

- **관리자**: `/admin`에서 매니저/스트리머 계정 생성, 이름 수정, 담당 매니저
  재배정, 비밀번호 재발급, 삭제. 관리자 계정 자체는 이 화면에서 만들 수 없고
  `prisma/seed.ts`로만 추가합니다 (셀프 서비스로 관리자를 늘리는 것은 의도적으로
  막아뒀습니다).
- **매니저**: 담당 스트리머별 탭에서 리마인더 등록/삭제, 처리 현황 확인.
  본인에게 매칭된 스트리머의 일정만 보고 조작할 수 있습니다.
- **스트리머**: 본인 일정을 직접 등록할 수 있고, 담당 매니저가 등록한 일정도
  함께 보입니다. 완료 처리 / 되돌리기는 둘 다 가능하지만, 삭제는 본인이
  등록한 항목만 할 수 있습니다 (매니저가 등록한 항목은 매니저만 삭제).

모든 접근 제어는 화면단뿐 아니라 API 라우트(`src/app/api/reminders`,
`src/app/api/admin`)에서도 역할과 매칭 여부를 다시 검증합니다. 로그인하지 않은
사용자는 모든 페이지에서 `/login`으로 리다이렉트됩니다 (`src/proxy.ts`).

### 계정 삭제 안전장치

담당 스트리머가 있는 매니저나, 리마인더를 등록한 이력이 있는 계정은 삭제할 수
없습니다 (`prisma/schema.prisma`의 `onDelete: Restrict`) — 먼저 스트리머를 다른
매니저로 옮기거나 관련 리마인더를 정리해야 삭제가 됩니다. Prisma는 nullable
외래키의 기본 삭제 동작이 "조용히 NULL로 바꾸기(SetNull)"라 이 부분을 명시적으로
Restrict로 지정해뒀습니다 — 기본값에 맡기면 매니저를 지우는 순간 담당 스트리머가
아무 매니저도 없는 상태로 조용히 풀려버립니다.

## 데이터베이스

Neon(Postgres)을 사용합니다. 스키마를 변경했다면:

```bash
npx prisma migrate dev
```

로컬 `.env`와 Vercel 프로덕션 환경 변수가 같은 DB를 가리키므로, 이 명령 하나로
로컬과 배포 스키마가 함께 갱신됩니다. 스키마 변경 후에는 커밋 & push해서
Vercel 재배포까지 이어가세요 (마이그레이션 자체는 빌드 단계에서 자동 실행되지
않습니다).
